## How the work is done (conventions that matter)

- **Leads:** always file a lead as an issue. Read an issue's comments and check stock reachability before recommending it.
- **Fixes:** work in isolated worktrees from `42cd156ac` (`git worktree add -b task/<slug> .worktrees/<slug> 42cd156ac…`). The evidence worktree comes from `origin/master` (`task/<slug>-evidence`).
- **Commits:** `git -c user.name="Diego Amicabile" -c user.email="$(git log -1 --format=%ae 9ab78ae60)" commit …`, with **no AI trailers**.
- **Evidence package:** lives in `docs/audit/c-reports/<slug>/` and contains `scenario.c`, `run-cases.py`, `reproduce.py`, `make_replay.py`, `fix.patch` and `borg.txt`.
  - `reproduce.py` holds BASE, DIRECTORY, OBSERVER, FILES and EXPECT; `make_replay.py` holds the SUITE…CASES header lines.
  - `fix.patch` must be exactly `git diff BASE FIX`.
  - `borg.txt` is copied from **`src/borg/borg.txt` of the base revision**, never from another branch.
  - The latest packages (vulnmod-610, dnstair-615, coldmelee-616) are good templates.
- **Run:** `LANG=C.UTF-8 LC_ALL=C.UTF-8 python3 reproduce.py --fixtures-ref <fixtures sha> --fix-ref <fix sha> --full-tests`.
  - It takes `flock /tmp/angband-validation.lock` and runs about 8–10 minutes.
  - Gates must show 965/965 unit checks and 5/5 frontend tests in both phases.
  - Remove the disposable `/tmp/angband-<slug>-*/source` worktree afterwards.
- **Publishing:**
  1. Render-check `replay.html` (Playwright, 0 console errors).
  2. Copy the run artifacts into the package and write the README and `receipt.json` (sha256 of every other file).
  3. `git add -f` (`*.log` is gitignored), run `node tools/private-scan.mjs`, commit and push (retry on 5xx).
  4. Create the two draft PRs **before** writing PR numbers into issue comments.
  5. Then relabel the issue (`bug`, `evidence:c-game-reproduced`, `status:in-review`) and post a receipt on checkpoint #207.
- **Tooling:** the scratchpad helpers used here (`render-check.js`, `publish.py`, `mkpkg.py`) were not committed. Recreate them from the latest package, or ask the owner whether to add them under `tools/`.
- **GitHub:** in the cloud session, `gh` was limited to `gh api -X GET search/...`, and writes went through MCP tools. Locally, follow the owner's usual setup.
- **Native prerequisites:** Git, Python 3, CMake, a C compiler and Make, `flock`, X11 development headers, and Playwright with Chromium for the render check.
