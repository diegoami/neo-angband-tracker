The precedence pass that kept its scratch array

Every dynamic formula the Borg parses goes through a precedence pass that builds a temporary operator list for each block. The list items and the list struct were freed - but not the separately allocated backing array, so every populated operator block of every parsed formula leaked it, starting with the full formula file at startup.

What the control establishes

A bare constant builds no operator list: both variants evaluate 42 with byte-identical logs - and even the operator formula's functional output (value 7) is byte-identical; only the leak report changes.

Experiment conditions and limits

Native calculation machinery only (no game state needed): parse the constant-operator formula "1 + 2 * 3" and evaluate it; the leak proof is the same parse built with AddressSanitizer and run under LeakSanitizer. The lost allocations are 80 bytes per populated operator block per parse - a bounded leak at startup and per reinitialize, not a crash; no death or survival claim.
