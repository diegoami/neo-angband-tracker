Which backup item does the Borg choose?

Captured from the native C engine and Borg. This is a replay of a controlled test, not a live autonomous game. The map uses the native ASCII renderer; HP, items, messages and decisions are recorded run data. The accepted correction is the sentinel shape: both unavailable-candidate scores initialize to 9999 (danger is capped at 2000), the early no-swap return is gone, and the pick is the plain b_p2 <= b_p1. It is natively equivalent to the previously validated guarded form: all nine case logs are byte-identical.


Map: @ = Borg; d = dragon; . = visible floor. Blank areas are not rendered as known terrain. The two versions use the same scenario, seed and scheduled attacks; only the emergency item comparison differs.

The tested selection conditions

The same nine native cases were measured against four versions of the production comparison in one experiment: the original comparison (4/9 pass), the plain reversal without guards (7/9; both single-backup cases select an absent item), the guarded fix (9/9), and the accepted sentinel fix (9/9). The sentinel and guarded fixes produce byte-identical native logs in all nine cases. The exact matrix and repeat instructions are in SIMPLE-COMPARISON.md on the evidence branch.

Read the native output and setup limits

The test constructs an identified inventory, level/depth and illuminated arena, schedules the listed dragon breaths, calls the production emergency-swap routine, decodes its actual queued inventory letter, and applies that choice with native inven_wield. Damage and resistances come from native monster spells. Other healing/escape choices and full UI turn timing are outside this isolated test. Danger scores are the Borg's estimates, not measured damage. The four control cases must be identical. No player-death or complete-run frequency claim is made.
