The reload that forgot its array

Reinitializing the Borg frees the dynamic calculations and parses them again. The free emptied the list but kept its backing pointer array - and adding to an empty list allocates a fresh array, overwriting the retained pointer. The previous allocation was lost on every reload.

What the control establishes

A single parse without a reload never touches the free path: both variants evaluate the formula to 3 with one calculation and byte-identical logs - the correction changes only what the free releases.

Experiment conditions and limits

Native calculation machinery only (no game state needed): parse the constant formula "1 + 2", free the calculations as a reinitialize does, parse "3 + 4" and evaluate it. The retained-pointer check reads the global array state directly; the leak proof is the same reload path built with AddressSanitizer and run under LeakSanitizer. The lost allocation is 80 bytes per reload - a slow leak on a manual reinitialize, not a crash; no death or survival claim. Two further leaks visible in the same report (temporary operator arrays, token pointer arrays) are separate reported leads and remain in both variants.
