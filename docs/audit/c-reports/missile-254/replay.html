The Borg can try to fire with no target chosen

A Warrior with a bow and arrows knows a kobold it cannot shoot from where it stands. The shot-lining movement flow asks whether a distance attack exists; the target list is empty and the simulation flag is off, exactly the state earlier evaluations leave behind. The original launch routine then enters the firing path with missile index -1: it reads a description from before the inventory array and queues a fire key, a quiver character computed from index -1, and the target key.

What the controls establish

With a real target both versions queue the genuine firing keys and value the shot above zero; in simulation both value it and queue nothing. The logs of both controls match byte for byte. Only the no-target probe changes.

Memory error evidence

Under AddressSanitizer the original aborts inside the launch routine with a heap-buffer-overflow READ while formatting the note for missile slot -1 (borg-fight-attack.c); the corrected build runs the same probe cleanly and queues nothing.

Experiment conditions and limits

Native Human Warrior level 10, depth 10, seed 1000, lit constructed arena, a short bow, twenty arrows and a torch, one awake kobold five grids away. The production launch routine is called unchanged; the empty target list and the off simulation flag reproduce the state left by earlier evaluations in the shot-lining flow (the Teleport Other defense resets the target list; any acted attack or defense leaves the simulation flag off). This isolates the launch guard, not full autonomous play. No death or survival claim.
