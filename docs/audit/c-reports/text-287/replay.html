The message line that never ended

The Borg reads the message line from the screen as wide characters and converts it back to bytes - with a limit of one byte per wide character. A multibyte character occupies more than one byte, so a line whose byte length lands exactly on the limit was truncated without its terminating zero, and the uninitialized caller buffer was then trimmed and measured as a string: stale stack bytes parsed as message text, producing phantom monsters in the supplied replay evidence. The correction passes the size of the caller buffer, converts at most one byte less and always terminates. A third panel shows the earlier fix shape (a limit of MB_CUR_MAX bytes per character), which terminated the short line but could write past the buffer on a wide terminal.

What the control establishes

A pure-ASCII row fits the old limit as well: both variants terminate identically with byte-identical logs - the correction changes only the multibyte boundary case.

Experiment conditions and limits

Native Human Warrior, seed one thousand, a UTF-8 locale (the multibyte conversion only widens in a multibyte locale), a hand-painted screen row of eighty characters with exactly one two-byte character, and a caller buffer deliberately junked with no zero anywhere so an unterminated conversion is visible as a full-buffer measurement. This isolates the conversion bound, not the full message-parsing chain; the phantom-monster consequence is the supplied harness evidence, not claimed here. No death or survival claim. The wide case reads a 301-column row into a 1024-byte buffer the way borg_get_messages() does; in the normal build a guard area after the buffer counts any write past it, and the AddressSanitizer build uses a standalone buffer so such a write is reported.
