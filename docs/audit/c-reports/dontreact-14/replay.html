Recorded native message-queue states

The borg stayed deaf after knockout recovery

When the message "You have been knocked out." arrives, the Borg sets a flag that gates every further reaction; no combat message is processed while it is up. The flag was a static copy that nothing ever cleared, so after the knockout recovery the Borg remained deaf to combat messages for the rest of the session. Upstream intended the flag to be the Borg’s own dont_react field, which the production pump clears on every pass. The correction renames the copy to that field, and the Borg resumes reacting after recovery.

What the recorded run establishes

Baseline reaction queues 1 message; during the knockout the queue is gated (both versions; that gating is intended); after the recovery pump the original still gates (1) while the corrected borg queues the next message (2). The during-knockout gating is identical in both versions, so the correction changes only the post-recovery behaviour.

Experiment conditions and limits

Native Human Warrior, seed 1000. The knockout message is parsed through the production parse/flush path; the pump replays the production sequence (borg_parse(NULL); borg.dont_react = false). Queued-message counts are read back from the borg’s message buffer. This isolates the flag lifecycle, not full autonomous play.
